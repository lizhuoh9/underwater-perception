# run_02 结果的解读限制

评估之后做了一次代码审查，并补了只读核对（只用标定集，没有打开 TEST），本文记录结论。
`evaluation/` 里生成的报告保持原样。

**没有发现的问题。** 验证和计分代码没有错误，锁定前没有加载任何 TEST 图像或标注。
`evaluation/summary.json` 里的汇总数字和 2000 次配对自助区间，都能从 `per_image.csv` 原样复算出来。

**补充核对全部通过：**

- 锁定文件齐全。
- 计划里的结构选择记录与 `exploration/selection.json` 一致。
- 对照上限等于森林的 7.88%。
- 用重新加载的模型，int8 和浮点两条 257 点标定曲线都能逐项复现。

## 1. 锁定的权重本身不满足选结构时的规则

**规则：** 量化后，漏检 5% 处的误检不能超过 12.36%，即 run_01 结构的探索值 11.36% 加 1 个百分点。

- **探索时那次训练：** lite 为 11.97%，符合规则。
- **正式锁定的那次训练：** 同一结构、同一随机种子，只是打开了 cuDNN 确定性，结果是 13.55%（浮点 13.14%），**不符合**规则。

同一结构重训一次，这个误检会变动 0.7～1.6 个百分点，比规则留的 1 个百分点余量还大，所以这条规则区分不出 lite 和 run_01 结构。
如果按锁定的权重重新套用规则，会选回 run_01 结构。
run_02 的价值主要在运算量（22.3 MMAC，run_01 为 69.7 MMAC），要靠板上测速确认。

规则写定的时间点：看过第一轮探索之后，第二轮之前。

- 第一轮：run_01 结构重训、lite、加权损失。
- 第二轮：lite_dw_down、lite_wide。

所以它不算完全事前写定。

## 2. 5% 漏检上限不是盲选

5% 来自 run_01：看过 run_01 的 TEST 结果（漏检约 11%，潜水员、机器人、鱼召回偏低）之后，才定下用于避障。
探索时盯的指标（漏检 5% 处的误检，潜水员、机器人、鱼的召回）也受这个影响。

run_02 的探索、训练和锁定都没有加载 TEST。但部署阈值下的 TEST 数字，是对同一批 110 张图的第二次观察，不是独立盲测。
需要新数据确认，最好是 OV2640 实拍、按拍摄批次划分。

## 3. 逐类召回只能作描述

最严格的 74 张里，各类出现的图数和单张占比如下：

| 类别 | 出现图数 | 单张最多占该类像素 |
|---|---:|---:|
| 机器人 | 5 | 61% |
| 水草 | 13 | 22% |
| 沉船 | 22 | 10% |
| 潜水员 | 29 | 16% |
| 礁石 | 39 | 5% |
| 海底岩石 | 42 | 7% |
| 鱼 | 44 | 8% |

逐类表没有区间。RESULTS.md 表格下面那句关于自助区间的说明，不适用于逐类表。
机器人一类，一张图就能让召回变动 5 个百分点以上。

## 4. 没有预先指定主要比较

RESULTS.md 列了 5 组比较 × 3 个嵌套子集。

- **主要比较：** 部署阈值对 run_01 +5，看最严格子集。漏检 −0.22 个百分点（−0.83～+0.45），误检 +1.06 个百分点（+0.03～+2.21）。
- **其余比较：** 只作探索性参考。

## 5. TEST 评估只认 `evaluation/`

评估脚本只会拒绝覆盖已有的输出目录。以后如果换一个输出目录再给 run_02 计分，那是重复观察，不是新证据。

评估时读入的 run_01 逐图结果没有改动，SHA-256 如下：

- `cnn_espdl_run_01/evaluation/per_image.csv`：`eabdf8e8ff84baccba8c2c3d5eeda3f3b68d4ad4164c5e075627cdbb8d9761e4`
- `cnn_espdl_run_01/threshold_cap5/evaluation/per_image.csv`：`a9b4034ae14ef16c95f947c922a406b80e18710717e1a319920b2237f8c9d8c2`

`summary.json` 的 `thresholds` 字段：int8 方法填的是阈值码（−128～127），浮点方法填的是 0～255 概率刻度上的阈值。

## 下一轮锁定前要改的地方

改 `train_cnn_lite.py` 会使 run_02 无法再复核，所以这些修改放进新版本脚本，不改现有脚本：

- 在最终权重上重新检查选结构规则，并写进 LOCKED。
- 资格从 `variants*.json` 重新计算，不直接相信 selection.json。
- 探索和正式训练用相同的确定性设置。
- 训练多个种子，或者把余量设得大于种子波动。
- TEST 计分前写入一次性的声明文件，评估脚本也纳入锁定哈希。
- 逐类结果给出按图像的区间。
- 预先指定主要比较。
